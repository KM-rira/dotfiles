# Pull Request Review

## 実行条件

ユーザーがPRレビューを依頼した場合に使う。PR URLがある場合は最初に`gh`でタイトル、説明、変更ファイル、差分を取得する。

## 手順

1. 対象リポジトリ、ブランチ、作業ツリーの未コミット変更を確認する。
2. PRの目的と差分を読み、関連する実装・呼び出し元・設定を追う。
3. 正しさ、境界条件、データ整合性、認可・入力検証、エラー処理、互換性を中心に不具合を探す。
4. 指摘候補ごとに、差分から導ける再現条件とユーザーへの影響を確認する。
5. 根拠のある問題だけを、重大度の高い順に報告する。

## 出力形式

各指摘は次の形式にする。

```text
[P1] 問題を短く説明
ファイル: path/to/file.ext:行

なぜ問題か、どの条件で発生するか、影響を簡潔に説明する。
```

重大度は次の目安を使う。

- **P1:** 広範囲な障害、データ損失、重大なセキュリティ問題
- **P2:** 通常の利用で機能が壊れる、または重要なケースが使えない
- **P3:** 限定条件での不具合、回避策がある問題
- **P4:** 軽微な問題

指摘がない場合は「指摘事項はありません」と明記し、確認範囲と実行していない検証があれば併記する。スタイルの好みや根拠の薄い懸念は不具合として報告しない。

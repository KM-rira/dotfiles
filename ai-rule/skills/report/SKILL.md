# Report作成ルール

## 実行条件

ユーザーが明示的にReport作成を依頼した場合にのみ実行する。通常の実装・調査・テストが完了しただけでは作成しない。

## 保存先

`~/work/report/<repository>/` に保存する。`<repository>` は対象Gitリポジトリ名とする。対象を特定できない場合は確認する。Reportは対象リポジトリの外に保存する。

## ファイル名

- Issue: `issue-<番号>-<短い英語タイトル>.md`
- PR: `pr-<番号>-<短い英語タイトル>.md`
- その他: `report-<YYYYMMDD>-<短い英語タイトル>.md`

英小文字・数字・ハイフンによるkebab-caseを使う。番号や参照先は確認できた情報だけを使う。同名ファイルを無断で上書きしない。

## フォーマット

```markdown
# <タイトル>

## メタデータ
- **Date:** YYYY-MM-DD
- **Time:** HH:mm:ss ±HH:mm
- **Repository:** <repository>
- **Type:** <issue / pr / report>
- **Reference:** <確認済みのURLまたはパス>

## 1. 問題
## 2. 原因
## 3. 作業プロセス
## 4. 作業内容
## 5. 根拠
## 6. 結果
```

結果は「成功」「部分解決」「未解決」「未検証」のいずれかを明記する。

## 作成ルール

- 依頼と実際の作業に基づき、不明事項は推測せず「不明」「未確認」とする。
- 事実・推測・提案を区別し、実行していないコマンドやテストを実施済みと書かない。
- 具体的な根拠と参照先を示す。存在を確認していないURLやパスを作らない。
- 機密情報を含めない。
- 保存後、保存先・ファイル名・必須項目・事実関係を確認し、絶対パスと概要をユーザーに報告する。
